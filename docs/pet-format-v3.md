# Pixel Pets format, version 3

This is the normative contract for a Pixel Pets package, the animation set, the behaviour priorities, and how the `pixel-pets` mod draws a pet. The tooling, the mod and the skills all implement this file; change it first when the contract changes.

Version 3 extends the Codex pet format (`spriteVersionNumber: 2`, from OpenAI's Apache-2.0 `hatch-pet` skill). Rows 0-10 keep Codex v2's meaning and order, so a Codex pet imports without redrawing.

## Package layout

```text
~/.claude/pets/<pet-id>/
├── pet.json
├── spritesheet.png        # the full 8 x 22 atlas (source of truth)
└── strips/
    ├── idle.png           # one horizontal strip per animation, cut from the atlas
    ├── walk-right.png
    └── ...
```

`strips/` is generated by `tools/package_pet.py` from the atlas and is what the mod reads at run time (the mod has no image library and cannot crop). A package without strips is not loadable; run the packager.

## Atlas

- Grid: 8 columns x 22 rows. Cell size `cell.width` x `cell.height`, each an integer from 16 to 128 inclusive.
- Atlas size: `8 * cell.width` x `22 * cell.height`. PNG, RGBA, transparent background.
- A standard row's used cells are its leading `frames` cells; cells after them are fully transparent.
- Rows 9 and 10 together hold the 16 look directions, all cells used.

## Pixel-art rules

Pets are pixel art. `tools/validate_pet.py` enforces these for v3 packages; imported Codex v2 pets that break them load with a warning and `"pixelArt": false` in `pet.json`.

1. Every cell is at most 128 x 128 pixels.
2. Alpha is binary: every pixel is fully opaque (255) or fully transparent (0).
3. At most `pixelArt.maxColors` opaque colours per cell (default 64, hard limit 256).
4. Art is stored at its native pixel size, not pre-upscaled. The validator rejects a cell whose art is uniformly made of n x n blocks (n >= 2); downscale it, and let the renderer scale up with nearest-neighbour.
5. Each strip PNG is at most 96 KiB, so a strip embedded as base64 (about 128 KiB) fits the desktop `Svg` element's 131,072-character limit with room for the row around it. Reduce colours, frame size, or detail if a strip is over.

## pet.json

```json
{
  "id": "pixel-clawd",
  "displayName": "Pixel Clawd",
  "description": "One short sentence.",
  "author": "Name or handle",
  "license": "CC-BY-4.0",
  "spriteVersionNumber": 3,
  "spritesheetPath": "spritesheet.png",
  "stripsPath": "strips",
  "cell": { "width": 64, "height": 64 },
  "pixelArt": { "maxColors": 64 },
  "animations": {}
}
```

- `id`: lowercase letters, digits and hyphens; equals the folder name.
- `animations`: optional overrides keyed by animation name. Each value may set any field of an animation (below). A key that names no standard animation declares a **custom animation**; it must give `row` (22 or more, extending the atlas downward by whole rows), `frames`, `durations` and `fallback`.
- Unknown top-level fields are ignored, so tools can add metadata.

## Animations

Each animation has: `row` (first atlas row), `frames` (1-16; more than 8 continues on the next row), `durations` (one value in ms per frame, or one value for all), `loop` (`true` for a state, `false` for a one-shot reaction; custom animations default to `false`), `priority` (`"P0"`-`"P6"` or an integer 0-6, below), `minMs` (minimum time on screen before another animation of the same or lower priority may replace it, default 600), `next` (one-shots only: what plays after; default: whatever loop wins), and `fallback` (the animation to use when this pet does not draw this one).

Custom animations default to `loop: false` and priority P4.

The `pop-out` strip ends on the pet's idle pose; the `duck-in` strip ends fully transparent.

The `look` strip (`strips/look.png`) is one 16-cell strip ordered 000, 022.5, 045 ... 337.5 degrees. Look directions: row 9 holds 000, 022.5, 045, 067.5, 090, 112.5, 135, 157.5 degrees; row 10 holds 180 through 337.5. `000` is up (12 o'clock), clockwise. Front/neutral is not a look cell; it is `idle`.

An animation counts as drawn when its strip exists, has the right size (frames x cell width by cell height) and is within the size limit; otherwise its fallback is used.

Fallback resolution: if a pet's cells for an animation are all transparent, or a custom animation is missing, follow `fallback` until an animation the pet draws is reached. `idle` must always be drawn.

Reduced motion (`prefers-reduced-motion: reduce`): show each animation's first frame only.

### What each animation is for

- `idle`: calm breathing/blinking; the default.
- `walk-right`, `walk-left`: locomotion; idle wandering now, travel during pop-out later. Mirror only when the art is symmetric.
- `waving`: a session starts or the person returns.
- `jumping`: a turn finished cleanly.
- `failed`: a tool failed or a turn errored.
- `waiting`: something is blocked on the person (permission prompt, question).
- `working`: a turn or subagent is running (any tool).
- `review`: inspecting finished output, or a reviewing subagent is running.
- `look`: a glance toward the source of an event.
- `sleeping`: idle past the sleep threshold (default 5 minutes).
- `waking`: plays first whenever anything above P6 happens while asleep.
- `summoning`: a subagent is dispatched.
- `celebrating`: a commit, a merged PR, or a passing test run.
- `confused`: a permission was denied or a step was retried.
- `eating`: context compaction ("digesting").
- `fidget`: random idle variety (stretch, yawn, scratch), every 20-60 s while idle.
- `pop-out`, `duck-in`: the pet appears or hides.
- `alert`: another source needs the person while the shown source is busy.
- `petted`: the person clicked or patted the pet.

## Behaviour priorities

P0 is the highest. P0 user interaction; P1 needs the person; P2 bad outcome; P3 good outcome; P4 activity; P5 transition; P6 ambient. Custom animations default to P4.

A **source** is anything that produces pet events: the main conversation, each running subagent, and (after the multi-chat refactor) each chat. The arbiter applies these rules:

1. **Loops are states, one-shots are reactions.** Each source holds at most one active loop. The shown loop is the highest-priority loop across all sources; on a tie the most recently started wins.
2. **A one-shot interrupts only a loop of equal or lower priority** (numerically greater or equal P), then the winning loop resumes. A one-shot of lower priority than the shown loop is dropped, not queued.
3. **Coalescing.** One-shots arriving within 1500 ms of each other are merged: the highest-priority one plays once (five subagents finishing play one `celebrating`).
4. **No flicker.** An animation stays at least its `minMs` before an animation of the same or lower priority replaces it. P5 transitions always finish unless a P0 or P1 event arrives.
5. **Waking first.** While `sleeping` is shown, any event above P6 plays `waking` before its own animation.
6. **Glance.** When the shown animation changes because of a source other than the one shown before, the pet may play `look` toward that source for one `minMs` first. In single-chat mode the main conversation is direction 180 (down, toward the transcript); subagents take directions spread over the lower half.
7. **Hidden.** After `duck-in` the pet is hidden until `pop-out`.

`alert` is raised when a source other than the shown one enters a P1 loop while the shown source holds a loop of P2 or lower. In single-chat mode that means a subagent waiting on the person while the main turn works.

## Drawing

The `pixel-pets` mod is self-contained: it exposes no interface to other mods and does not read or draw into theirs.

- It draws the pet in its own pane (id `pet`, titled with the pet's display name), opened at session start unless the `openAtStart` option is `off`, and toggled with `/pet open` and `/pet close`. It does not draw in the band above the prompt.
- Desktop, VS Code and mobile: one `Svg` holding the current animation's strip as a `data:image/png;base64` image, cropped to one frame, scaled with nearest-neighbour to the `size` option (default 96 px) within the pane's width, and animated by CSS keyframes. The keyframes' negative `animation-delay` is computed from the time of drawing, so a redraw stays in phase.
- Terminal: the current frame through the `Image` element where the terminal can show pictures; otherwise one line of text naming the pet and its animation.
- Hidden (after `duck-in`): the pane shows nothing until `pop-out`.

## Limitations and future work

- **Chat-specific, in-window.** In version 3 the pet lives in a pane inside one session's window. It cannot float outside the window and does not see other chats.
- **Planned refactor: pop-out and multi-chat.** The target is a Codex-style pet that pops out of the panel and reacts to every live chat at once. The arbiter already treats events as coming from sources with priorities, so the refactor replaces the source registry (main conversation + subagents) with one that also tracks other sessions, and replaces the pane with a floating surface. Both depend on Claude Code capabilities that do not exist yet: a cross-session event feed for mods, and a surface that can draw outside the transcript and panes.
